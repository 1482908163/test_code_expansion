# 第四次迭代后续：面依赖约束的封闭子域任务调度

日期：2026-09-09。开发基线：`09b4263b8242269fb4e68a0747ae390a6f79beda`，研究分支 `agent/dependency-aware-mesh-balance`。本记录是新实现的实验约定；此前已经运行的第四次节点组映射数据保持原样，见 [真实结果](20260908_iteration4_results.md)。

## 问题与假设

上一批组合方法对仅稀疏通信在8192进程的自然核心中位数仅下降1.44%，拆分计时略慢。慢分区预测不足、16分区整组映射以及额外参考预热使其未达到稳定净收益目标。稀疏面交换已有明确收益，应保留。

本次假设：将局部网格重新生成拆为多个封闭任务，允许空闲进程领取尚未开始的任务，可用真实完成反馈减少静态映射中的长尾。面依赖预算限制调度引起的跨节点边界增长。**不再依赖离线耗时拟合，也不增加校准轮次。**

## 算法与实现边界

1. 粗网格完成后，根进程用固定种子将粗单元划为 K 个逻辑任务，广播归属。K 在四组和所有进程规模间保持不变。任务是带定向闭合表面的子域；不要求一个任务只含一种材料，原材料标签保留。空任务立即报错。
2. rank 0 管理待执行集合，其余 P−1 个进程计算。所有对照均采用此资源配置。初始归属为 `home(t)=1+floor(t*(P−1)/K)`，按逻辑任务编号分组。
3. 每个任务执行分区面构造、L 次表面细化及局部体网格重新生成。完成者发送任务编号、耗时、单元数和网格签名，再领取下一任务。任务权重只用粗边界面数量确定优先次序，不称为经过训练的耗时模型。真实完成速度通过请求节奏影响分配。
4. 静态对照只领取自身初始任务。动态方法从全局待执行队列前64项及原属本节点的首个待执行任务中选择；优先级为边界面权重乘以 `1+0.25*同节点邻接面比例`，并满足下面的预算。候选上限是固定参数，**不是全局最优调度保证**。
5. 以粗任务邻接图边权（共同粗面数）计算跨节点切分 C。未执行任务也有初始归属，每次改派精确更新完整计划：`C_new <= C_initial + floor(0.10*C_initial)`。同节点任务改派增量为0，保留此候选保证预算严格时仍能推进。已开始的任务不迁移；不抢占正在运行的 Netgen 操作。
6. 工作进程保留尚未进行体细化的小网格。全部任务结束后发布最终归属，使用既有全收集或稀疏方法构造真实物理进程之间的面依赖。局部按重心坐标键合并共享顶点，删除同进程、同材料的任务内部面；不同材料界面保留一份，维护内外域信息。
7. 合并后沿用原 R 次体细化、全局64位编号和邻接交换。因此没有把数十亿细单元作为动态迁移载荷。本次直接调度的是前面的局部重新生成；后续体细化仍按最终归属执行，若其长尾上升，核心结果会体现代价。

跨节点粗面预算不等于最终顶点闭包、消息总字节或网络时间上限，仍需实测后者。队列管理、粗任务面构造、合并与集中式分区均有成本，不能视为免费。当前每进程仍持有已有粗网格及任务粗面目录；本次不同时引入分布式划分器或节点层级通信，以保持研究主线明确。

## 四组与统一入口

| 组名 | 调度 | 面交换 |
|---|---|---|
| baseline | 固定任务归属 | Allgatherv |
| balance | 受面预算约束的按需领取 | Allgatherv |
| sparse | 固定任务归属 | 稀疏依赖交换 |
| combined | 受面预算约束的按需领取 | 稀疏依赖交换 |

这些组名沿用已有脚本，但本次 baseline 是静态任务对照，**不是历史一进程一个分区的原始网格生成流程**。同 K 下比较 combined/sparse 才能隔离调度增量；不能直接将与历史不同网格的速度变化全部归功于调度。

所有参数在 `strong_scaling/run_experiments.sh` 开头修改。默认 production：1024/2048/4096/8192进程，每节点16进程，64/128/256/512节点；K=16384，L=R=3，种子41，面增长预算10%，每组1次常规预热和5次正式，共160次正式、32次常规预热。pilot：16/32/64进程，K=128，L=R=1。任务数须满足 `P−1 <= K <= 粗单元数`。

```bash
bash build_project.sh
bash strong_scaling/run_experiments.sh
```

不需要命令行串联环境参数；不执行模型拟合、离线性能推演、历史分区预检或额外全尺寸参考预热。常规预热维持原协议。4个作业仍并行提交并共用最早启动时刻，保留 Slurm 临时脚本寻址、失败后继续、压缩续跑和自动清理。

## 计时、可比性与成功判据

核心起点仍在粗网格后的屏障之后，终点为邻接交换完成；所有新增开销都在核心区间内。粗网格生成不改动、不计入核心时间。

画像使用 `mesh_tasks_v1`，不混入历史一分区的14特征模型样本。除既有阶段外报告：

- `task_geometry_setup`：构建任务表面和面依赖。
- `task_dispatch`：工作进程请求/回复耗时，包含可能的队列服务等待。
- `task_completion_wait`：收到停止回复后，等待最终归属和少量完成元数据的广播。这是等待加广播，不是纯屏障时间。
- `task_scheduler_service`：根进程服务整个队列的区间，和工作进程计算重叠，不能当额外串行开销相加。
- `task_merge`：共享顶点与局部网格合并。
- 每任务完成覆盖、初始/最终跨节点粗面数与预算、实际跨节点移动数、任务生成全局体单元数、网格签名。

计算最大/平均指标仅对 P−1 个计算进程求值；耗费资源仍按全部 P 计数。任务控制字节与原面交换字节分列。分区/拓扑发现本身的小型集体通信也包含在核心时间内，控制字节列不是全部网络流量。

完成分析检查任务数与三段计算调用次数一致、根进程未执行任务、`细化前任务体单元总数 * 8^R = 邻接前体单元总数`、面预算不越界。任务网格签名按逻辑顺序组合生成后的坐标/连接/域指纹及单元数，与执行进程无关。四组、重复及跨规模出现签名或体单元总数差异时，在 `issues.txt` 和总览标明不可作为固定工作量对照；不能掩盖库的随机性或其它生成差异。这些是实际运行结果检查，不是离线性能推演；签名也不能替代几何质量和端到端正确性验证。

首先看 `RESULT_SUMMARY.txt`，完整后比较自然计时 combined/sparse 的核心中位数与逐次差异。成功需在同任务工作量下得到可重复的核心净下降，同时实际计算最大值或任务结束等待下降，新增准备/调度/合并费用未吞掉收益，面通信没有显著恶化。不能只以顶点等待下降作成功依据：本次等待主要可能提前到任务结束广播。各阶段最大时间对应的进程可能不同，不直接相加为核心时间。

若失败，优先按新增阶段判断：任务过大导致不可抢占尾部仍长、任务过小导致闭合边界及建网次数太多、面预算过紧限制改派、体细化或集中式队列成为新瓶颈。依据真实数据选择一个原因处理，不同时增加模型、轮次和多个辅助方案。本轮固定参数事先记录，不能用同一批结果反复调参后声称独立验证。

## 创新表述与验证状态

按需队列、超分解、图切分预算和稀疏依赖交换均有既有研究基础，本身不宣称原创。可研究的组合是本流程中“生成前封闭任务 + 真实完成反馈 + 面依赖预算 + 体细化前合并”，其价值必须由同工作量消融、通信成本及多规模净收益支持，目前只是待验证的方法候选。

本地完成必要正确性检查：随机请求顺序下任务恰好一次及预算/推进性；小型网格接口夹具的共享点去重、内部面删除、材料界面和单元守恒；统一入口在无校准目录下提交与运行四组、零历史预检/参考预热、压缩续跑、签名不一致拦截。检查复用既有测试文件，临时网格夹具不加入仓库，不新建测试目录。

主程序和新增适配器使用官方 MPI/METIS 头文件以及 Netgen/OCC 声明桩做语法检查；这不是定制网格库的真实链接/集群运行。本次未做离线性能核验，没有填写预计加速比，实际网格规模、正确性和性能均待集群实验确认。
