# 第四次迭代：固定分区的资源感知节点组映射

研究主线是降低最慢进程完成时间及同步等待，保留第一轮已验证的稀疏面交换。本次实现直接进入四组性能评价，不再单独增加校准轮次、特征清单或均衡搜索轮数。当前状态：算法、统一入口和本地验证完成；尚未在集群运行，不能宣称实际加速。

## 依据与变化

## 模型和算法

四个计算阶段的定义沿用上轮：表面创建/细化、局部体网格生成、体细化、邻接/局部编号。令几何特征为 x_i，阶段非负系数为 beta_k，节点慢速因子为 s_h，采用：

`T_hat(i,h) = s_h * W_i; W_i = sum_k beta_k^T x_i`。

每个目标进程规模单独训练：使用该规模的种子 -1、17 及跨节点重复，种子41的任何数值特征和耗时都不参与拟合。进行6次有界交替更新：节点因子初始化为1；将每个逻辑分区的阶段测量除以所在节点因子、跨重复取中位数，拟合尾部加权的非负四阶段模型；再用每个节点上 `log(实测总计算/几何预测)` 的均值更新节点因子，归一化其几何平均为1。最后再拟合一次阶段系数。复用原求解器，仅为同规模共线特征增加可选迭代上限，旧方法默认参数不变。

训练节点因子只用于剥离历史采样的节点影响，不作为下次作业的永久速度表。模型另外保存参考种子 -1 各逻辑分区的校正计算量。当前作业先执行一次 -1/sparse/natural 参考预热，在每个节点上用16个进程的 `实测总计算/参考计算量` 几何平均估计当前 s_h，然后冻结，全部四组对照共用。单个乘性因子是模型假设，不能覆盖所有计算/内存/阶段差异，也不能保证长作业期间速度不变。

对节点组 b，令 `B_b=max_{i in b} W_i`。目标为：

`min_permutation pi max_b B_b * s_pi(b)`。

将 B 从大到小排序、s 从小到大排序并配对。这在上述单因子模型及节点组固定的条件下是精确的瓶颈配对解：若较重组被放到较慢节点，将这对分配交换，两个乘积的最大值不会增大；反复消去这类逆序即可。计算量为 `O(P + N log N)`，P为进程数，N为节点数。不声称求解了任意异构任务或真实通信网络上的全局最优调度。

仅当预测最大计算下降超过 `max(0.35秒, 原预计最大时间的5%) + 实测配对计算费用` 时采用，否则保留原循环映射。阈值不是统计置信界。取消旧路径中“独立最坏过估/低估包络相减”的采用逻辑，因为此次不改变分区几何；仍通过实际四组对照检验收益。预测、配对、分区和分发的全部时间都包含在正式核心时间中。

整组映射保持逻辑分区成员、分区邻接图的切面及节点内/节点间邻接关系数量不变。散列目录中转位置、真实网络路径和 MPI 集合实现仍可能产生不同通信时间，因此仍测量完整面流水段；不能将这一不变量写成“物理网络时间完全不变”。映射后全局编号允许不同，实际细单元总量、冗余和网格质量需在正式结果中核对，不能仅凭粗分区不变替代端到端正确性验证。

## 离线核验结果

[复算脚本](20260908_iteration4_replay.py) 和 [逐重复数据](20260908_iteration4_replay.json) 已归档。对41分区的3次历史运行，使用 -1 第一次历史测量近似当前节点预热。该参考测量也参与过训练，因而能力标定可能偏乐观；41的目标测量未参与拟合。以下均为每规模3次结果的中位数：

| 进程数 | 同一联合模型只用几何项 WAPE | 加入节点因子后的 WAPE | 预测最慢计算下降/s | 预计采用次数 |
|---:|---:|---:|---:|---:|
| 1024 | 5.12% | 5.11% | 0.180 | 0/3 |
| 2048 | 4.20% | 4.23% | 0.201 | 0/3 |
| 4096 | 7.28% | 5.23% | 2.325 | 3/3 |
| 8192 | 18.95% | 7.66% | 3.290 | 3/3 |

WAPE是所有进程绝对预测误差之和除以实际计算时间之和。左列是联合模型将节点因子设为1的消融，不是上轮跨规模模型的误差；协议不同，不能混作同一个指标比较。预计采用次数忽略运行时微小配对费用，实际采用由 C++ 计时决定。

这说明值得测试的收益集中在大规模异构节点分配，较小规模可能没有足够改进空间。**表中2.325/3.290秒不是实测核心加速，也不是实际等待下降。** 此次改为同规模留分区验证，不能宣称跨规模或跨几何泛化已经解决。41此前已被观察分析，也不能称作完全盲测的新几何测试集。

## 直接运行的实验

在已有研究分支更新并重新构建：`bash build_project.sh`；随后仍只运行 `bash strong_scaling/run_experiments.sh`。常用参数仍集中在脚本开头，无需命令行拼接环境变量。

生产默认配置：1024/2048/4096/8192进程，16进程/节点，对应64/128/256/512节点；L=R=3，MAXH=1000，MINH=0，单线程。`CALIBRATION_ROOT` 默认指向仓库中已经上传的第三次结果。登录节点自动拟合同规模模型，各规模作业并行提交，共用最早启动时刻，无串行依赖。

| 算法 | 节点组映射 | 面交换 |
|---|---|---|
| baseline | 原循环映射 | Allgatherv |
| balance | 当前节点能力感知映射 | Allgatherv |
| sparse | 原循环映射 | 已有稀疏依赖交换 |
| combined | 当前节点能力感知映射 | 已有稀疏依赖交换 |

四组都使用同一模型、当前能力测量、逻辑分区41；同一重复使用相同的初始节点轮换。每组 natural/split 各5次正式、1次常规预热，全部160次正式、32次常规预热，另4次节点参考预热，每规模仍只有一个作业。参考预热不替代每组常规预热，以免算法间预热不对称；其含粗网格在内的准备墙钟时间单列在 `node_capacities.json` 和总览中。

核心时间仍从粗网格完成后的屏障到邻接交换完成，排除粗网格及统计/压缩。预测与分区/映射费用包含在内。分析器分别保留自然运行和屏障拆分结果，不把不同进程或不同阶段的最大值简单相加成关键路径比例。

判断顺序：

1. natural 下 combined 对 sparse、balance 对 baseline 的核心时间净下降是否稳定；不能只与原始大 Allgatherv 对照，掩盖均衡本身无收益。
2. 对应最慢计算时间、顶点到达时间差及 split 下等待是否下降，面流水段是否回退。
3. 总体单元数、冗余、质量是否可比；节点参考预热的准备费用和可摊销次数。
4. 映射采用率和预测改善只用来解释结果，不能单独作为成功标准。

一次独立网格生成必须把其必要能力测量成本计入应用端到端收益；当前实验同时报告核心时间和单列准备成本。后续若不能复用参考预热，其额外成本可能吃掉收益。当前原代码仍随P增加而生成更多实际体单元，本批跨P曲线仍不应称作固定工作量严格强扩展。

运行结束优先查看每规模 `RESULT_SUMMARY.txt` 和 `analysis/summary.csv`；异常时才查看 `analysis/issues.txt`。原成功数据压缩清理、失败后继续、压缩结果续跑和Slurm临时脚本路径处理保留。节点能力文件绑定模型、当前程序/输入及实际主机排列；改用新节点分配或新程序请使用新结果目录。

历史 `BALANCE_METHOD=boundary` 保留原边界移动和跨规模模型协议；`EXPERIMENT_STAGE=legacy` 保留第一轮路径。它们不是本轮默认实验。pilot 默认仍是小规模校准，不能直接用正式规模模型替代。

## 创新边界与验证

资源感知建模与异构图映射已有基础，参见 [DRUM / Faik等，IPDPS 2004](https://j.teresco.org/research/publications/ipdps04/ipdps.pdf) 与 [Scotch官方项目](https://www.labri.fr/perso/pelegrin/scotch/)。排序配对本身不能写成新算法发明。本项目可研究的贡献是：面向该网格生成流程的阶段几何/资源分离估计，在不改变分区邻接切分的条件下优化关键完成时间，并与稀疏面依赖交换组合；需要真实收益、代价摊销和更多几何/配置支撑创新论证。

已验证：小节点数穷举排列与瓶颈配对最优值一致；节点组及进程映射双射、节点内关系不变；同速/收益不足回退；容量文件和主机绑定检查；模拟Slurm完整路径覆盖一次参考预热、四组两种计时、压缩清理、续跑；毒化41数据不改变训练模型；使用官方MPI/METIS头文件对32/64位METIS索引语法检查。语法检查的Netgen/OCC声明为本地桩，不能替代真实集群链接及网格运行。本次没有新建测试目录。
