## 1. 上轮证据与本轮问题

上一批 `mesh_algorithms_20260907-203522`，数据提交 `6e9eb64c6170683c21f30992836d7392c03d7b64`，运行源码 `409bac26f4ba1eb00ab4c993d7801a72914175c3`，36次正式与12次预热全部完成。但1024/2048/4096/8192进程中，每个同号进程的14维特征在3种子×3重复间完全相同；三个种子只提供了一组可观测分区特征。同一进程九次也始终处于同一节点。

去除特征重复后的诊断拟合仍低估真实最慢进程10.07%–24.11%，最慢1%召回率只有9.09%–26.83%。8192进程局部体网格生成占所统计计算时间约92%，完整分区流程约3秒。因此不能仅增加修正轮数，也不能因多次运行成功就认为尾部预测得到验证。完整数值与复算文件见 [上轮实验分析](20260907_v3_calibration.md)。

上轮已经核对了官方 METIS 的粗化阈值、初始划分选项及随机种子初始化路径；在当前小粗图、大分区数的条件下，更换外层种子可能不改变初始图或划分。对应上游版本为 [272d4a9](https://github.com/KarypisLab/METIS/commit/272d4a91c5f66c92327493339a476c553ebf1f5d)。这是与观测一致的机制解释，集群实际库仍需由本次预检记录核对，不能把上游版本当作已确认的集群版本。

本轮先检验两个必要条件：是否获得了实际不同的几何子域；同一子域换节点后，耗时与预测残差是否仍然稳定。保留已有14特征、尾部加权和经验误差约束的候选采用判据，暂不更改回归损失、增加搜索轮数或替换分区库。

## 2. 方法一：可复现重排与实际分区预检

### 2.1 改变划分器输入顺序，不改粗网格算法

给定粗单元序列 `0..N-1`，构造可复现排列 `π`。种子 -1 使用恒等排列和 METIS 库默认种子；17/41 使用固定 SplitMix64 整数序列驱动 Fisher–Yates 置换，并保留显式 METIS 种子。固定整数算法避免不同标准库对 `shuffle` 的实现差异。

送入 `METIS_PartMeshDual` 的第 `j` 行使用原粗单元 `π(j)` 的四个顶点。划分器返回行标签 `q[j]` 后，立即恢复 `part[π(j)] = q[j]`。顶点坐标、原粗单元编号及几何输入没有重新编号；粗网格生成阶段不作算法改动。重排改变的是划分器的遍历输入，同一拓扑仍可能产生相同结果，所以不能凭种子值宣布样本有效。

### 2.2 先检查，后生成细网格

每个已提交的规模作业先启动一个 MPI 进程，生成相同参数的粗网格，依次按该作业的正式分区数 P 执行全部种子。比如8192进程作业的预检仍划成8192份，不能用16份划分的差异替代正式规模检查。

预检验证：

1. 标签范围正确、每个分区非空、所有粗单元恰有一个归属。
2. 按标签首次出现顺序规范化完整归属向量，精确比较各方案。仅重命名分区编号不算新分区。
3. 用正式代码计算每个分区的14维特征，检查有限性和非负性，再比较排序后的特征多重集合。归属不同但可观测特征集合完全相同，也不接受为新校准样本。

任何一项失败，当前规模停止，不启动后续昂贵细网格采样。预检成功后保存每个种子的原标签向量；Python 再核对规范化归属签名和文件哈希，生成 `manifest.json`。清单绑定输入/二进制哈希、源码版本、P、L/R、网格参数、线程数、采样方式及种子，记录 METIS 编译头文件版本和索引宽度，并尝试记录实际解析到的动态库路径/哈希。静态链接或查询失败明确记为未知；头文件版本不能证明实际动态库版本。

每次正式运行在粗网格后的已有屏障之前读取参考标签，随后重新执行并计时正式划分，逐单元核对与预检一致；先核对种子分区，再做可选均衡修正和节点映射。不能用缓存归属跳过本应计入核心时间的分区工作。若粗网格或库的非确定性导致归属不一致，运行会停止；应定位原因或使用新结果目录，不删除核对条件。

这些检查避免“种子不同但几何样本重复”。它们不保证不同方案具有足够统计独立性，也不保证新边界一定生成有效高质量细网格。本次补查了局部体网格生成返回值，失败不能记录为成功；几何、体单元数和质量仍需对照。

## 3. 方法二：逻辑分区的节点轮换

保留划分器产生的逻辑分区号 `i`，第 `r` 次正式重复将其映射到物理 MPI 进程：

`physical(i,r) = (i + shift_r) mod P`。

分区归属标签和散发的特征统计使用相同映射；几何成员不因轮换而改变。画像分别记录逻辑分区、物理进程、偏移量和实际节点名。srun/yhrun 启动时指定每节点进程数及节点级 block 分布，使连续进程成组分配到节点；其语义见 [Slurm 官方说明](https://slurm.schedmd.com/srun.html)。仍以每次 MPI 实际报告的主机名判断覆盖，而不是仅根据启动参数推断。

每节点16进程、默认三次校准的偏移如下。偏移单位为进程号，均按整节点轮换。

| MPI进程数 | 节点数 | 重复1 | 重复2 | 重复3 |
|---:|---:|---:|---:|---:|
| 1024 | 64 | 0 | 336 | 672 |
| 2048 | 128 | 0 | 672 | 1344 |
| 4096 | 256 | 0 | 1360 | 2720 |
| 8192 | 512 | 0 | 2720 | 5440 |

一般计算为 `stride=max(RPN, floor(floor(P/RPN)/3)*RPN)`，`shift_r=((r-1) mod 3)*stride mod P`。预热偏移为0。评价5次按0/1/2/0/1轮换，同一轮的全部算法、计时模式使用同一映射以便配对比较。小规模只有1/2节点时只能要求覆盖1/2个不同节点；不能宣称已经完成三节点对照。

训练按 `(P, seed, logical_partition)` 合并跨节点重复，要求特征完全一致、每分区至少3次正式计时，并实际覆盖 `min(3, ceil(P/RPN))` 个节点。每阶段取这些计时的中位数；节点名保留用于残差归因，不作为生成前的几何预测输入。实际体单元数同样只是结果指标，避免把生成结束后才能得到的数据用于生成前预测。

轮换降低固定子域与固定节点性能绑定的影响，但三个节点不能覆盖全部硬件差异；每节点内部的进程槽位仍可能固定，网络干扰和运行顺序也未被完全分离。因此本方法是可追溯的对照采样，不能直接声称已经完全剔除节点效应。

## 4. 计时、训练和结果判定

- 核心时间仍从原有粗网格结束屏障之后开始，邻接体单元交换完成后截止。正式分区、特征统计、修正和分发都计入；粗网格、预检、参考文件读取、最终统计、压缩和分析不计入。
- 预检在已申请的作业内执行，不新增 Slurm 作业。它仍消耗资源及端到端机时，不能在报告总实验成本时忽略；这里只排除在定义好的网格核心性能指标之外。
- 训练仍完全排除目标 P 的校准样本。例如评价8192只使用1024/2048/4096，内部再分别整组留出规模和种子；归一化、范围与经验误差包络仅由训练组产生。
- 预检归属哈希、样本身份、实际节点覆盖和特征多样性全部通过，才接受新采样协议 `partition_sampling_v1`。缺少参考文件、混入旧数据、重复标签方案或节点未轮换均不能用于本次评价。旧数据保留作诊断，不补写或伪造新证据。
- `RESULT_SUMMARY.txt` 分别显示运行是否完整与校准是否通过采样检查。二者均通过只意味着可以训练并进一步评价，不代表模型准确或均衡已加速。机器可读结果为 `analysis/calibration_status.json`。
- 负载均衡成功仍须看同批自然运行的完整核心时间，以及 `balance/baseline`、`combined/sparse` 的净收益；`split` 用来分开同步到达等待和集合通信执行，不能混入自然运行汇总。

上轮默认分区的真实体单元总量随P从24.13亿增加到32.26亿；新的重排方案还可能改变分区边界及最终工作量。本次配置指定的是几何和L/R，不能预先保证固定网格单元总量。论文必须同步报告实际单元量、边界与质量，不能直接当作严格固定工作量强扩展。

## 5. 统一执行配置与数据保存

仍在 `strong_scaling/run_experiments.sh` 开头改配置，不增加用户提交入口。

```bash
bash build_project.sh
bash strong_scaling/run_experiments.sh
```

默认 `production + calibration`：P=1024/2048/4096/8192，每节点16进程，L=R=3，MAXH=1000，MINH=0，OMP线程数1，sparse/natural，种子 -1/17/41，每种子预热1次、正式3次。四个规模并行提交，沿用统一最早启动时刻；合计4次分区预检、12次预热、36次正式生成。预检未通过的规模不会执行这些预定细网格运行。

`PARTITION_VARIANT=cell_order_v1`、`PLACEMENT_ROTATION=1` 已设为默认。想先做流程验证，可在同一配置区设 `EXPERIMENT_PRESET=pilot`，使用16/32/64进程和L=R=1；pilot 结果不能用于正式L/R的训练。若预检失败，先看总览指定的日志，确认重复归属、重复特征或运行错误的具体原因，再决定是否更换候选种子。

全规模采样通过后，在同一配置区设 `EXPERIMENT_STAGE=evaluation` 并填写本次 `CALIBRATION_ROOT`，仍运行同一个脚本。评价先冻结排除目标规模的模型，再提交四算法/两计时/种子-1/5次正式对照，合计160次正式与32次预热。模型内部验证表在 `models/MODEL_REPORT.md`。

复用相同结果目录只用于相同配置断点续跑。配置或二进制改变必须使用新目录；已通过预检的参考文件会再次核对，已成功生成不重复计算，失败生成仍沿用原有继续与重试机制。

上传时保留每个规模的 `RESULT_SUMMARY.txt`、`analysis/`、计划/配置/状态，以及 `partition_preflight/` 的清单、标签、报告和日志；评价还保留根目录 `models/`。只新增少量粗单元参考标签，不保留额外细网格副本。成功运行的过程网格继续自动清理，画像和日志继续无损压缩，失败现场保留。日常先看总览，不需要逐个打开画像。

## 7. 论文定位和下一次分析

粗单元重排、哈希验证和节点轮换本身不能单独包装为负载均衡算法创新。它们补足实验有效性，使“几何难度→计算耗时→最慢进程→同步等待”的研究链条可检验。已有稀疏依赖交换的通信收益继续以第一轮对照为证；本次不据此新增通信加速数字。

新数据上传后依次判断：预检是否确实得到不同成员关系；跨节点后同一几何子域的耗时/残差是否稳定；整组留出的最慢进程低估和最慢1%召回是否改善；均衡候选是否有超过误差与修正成本的真实净收益。若采样有效后尾部仍不可预测，再考虑直接采集Netgen内部尺寸场/分阶段生成代价或改变任务粒度；若分区成本继续占约3秒，再实现分布式分区。节点内聚合和节点间分层面交换仍排在其后，不宣称本次已经实现。
