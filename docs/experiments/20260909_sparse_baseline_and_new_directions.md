# 固化稀疏通信，停止封闭任务调参，转向建网内部协作

日期：2026-09-09。基于分析提交 `6d299ed24d411142b056c673b3cf9c258ad408bb`，在 `agent/dependency-aware-mesh-balance` 分支线性更新；不改原 profiler 分支，不覆盖上传数据。本次只固化可用基线并研究替代算法，没有新的集群性能结果，也没有运行离线性能拟合或推演。

## 判断与责任

此前均衡迭代没有形成稳定净收益，最后的封闭任务方案使完整核心时间明显恶化。应停止这一路线的默认使用，而不能把问题继续归结为门槛、轮数或队列细节。此前过早把未验证方案设为默认，这一做法需要纠正。各轮并非所有指标严格单调变坏，但最后任务版本的整体退化是明确事实。

关键错误是调度粒度：外层调度的是一次完整的局部体网格生成。空闲进程无法协助已经开始的慢任务；为制造可调度任务而增加封闭子域，又增加独立建网次数和边界约束。这个抽象与降低本流程总时间的目标不匹配。

相比之下，通信方法已有独立对照：首轮8192进程 baseline/sparse 自然核心为18.443607/13.208286秒（下降28.39%）；面处理流水段为6.633001/0.611262秒（下降90.78%）；面逻辑载荷接收量37.07146/0.06133 GiB（下降99.8346%）。见 [首轮原始口径](20260906_first_run.md)。它说明全复制瓶颈大幅缓解，不证明通信达到理论最优；这些也不是全程序所有网络流量。

## 本次固化内容

1. 统一入口默认 `communication/none`，只保留 baseline/sparse 两组正式对照。恢复一进程一分区，所有 P 个进程参与建网；不再生成固定16384个任务。
2. 新增显式 `--communication-only` 模式：两组共用同一原始 METIS 划分与编号流程，保留根进程划分和标签广播，绕过均衡特征图、分区修正、模型统计 Scatter、节点能力映射。禁用组合算法、任务、模型与重映射混入此模式。
3. `SparseGatherFaceMap`、稀疏交换与依赖匹配实现保持不变；64位全局编号、粗网格算法、核心计时边界、成功结果清理和压缩续跑保持原有行为。退出未使用模型是基线整理，不包装成论文创新。
4. 分析器识别 `mesh_comm_v1`：检查每进程完整建网阶段各执行一次、没有历史均衡/任务阶段，不要求或导出模型样本。依旧保留实测核心、计算、等待和通信指标。
5. 历史实现仅作显式复现，不作为推荐默认，也不删除历史实验数据。没有增加测试目录或独立测试文件。

重新构建后仍只需运行 `bash strong_scaling/run_experiments.sh`；参数仍在文件顶部统一修改。默认4个规模、16进程/节点、L=R=3、两算法×两计时模式×5次正式，共80次正式及16次常规预热。固化后的可执行文件需要集群实际构建；不能用本地检查替代新的性能实测，也不需要为了这次研究重做离线核验。

## 替代算法研究

下面是已有算法及其对本流程的适用性判断。文献的加速比不移植为本项目预期数字。

| 路线 | 文献中的实际机制 | 与失败任务方案的差别 | 本流程判断 |
|---|---|---|---|
| HXT 空腔操作并行 | 按 Moore 空间填充曲线分配待插点或坏单元；跨内部划分的空腔操作延后，下轮重新划分并重试 | 多核更新同一份网格状态，调度局部操作；没有为每个调度块重建独立封闭体 | 优先研究其内核机制；共享内存方法，不能直接解决跨节点负载失衡 |
| CDT3D＋PREMA 分布式半推测适应 | 子域内部先做合法局部更新，再按邻域依赖移动接口单元；运行时支持活动对象迁移与调度 | 转移已有网格状态及待处理操作，避免每次领取重建完整局部网格 | 更直接面向跨进程协作，但需网格更新内核和状态迁移契约，改动较大 |
| 耗时反馈的 SFC 重分区 | 用前几轮真实耗时回归调整空间填充曲线切分权重 | 能利用重复计算的反馈，但仍重新分配子域 | 当前核心为单次重建；首次慢任务结束后才有反馈，不能解决本次尾部。暂不优先 |

来源：Marot、Remacle，2020，[Quality tetrahedral mesh generation with HXT](https://arxiv.org/html/2008.08508v1)，特别是4.1节；Garner 等，2023，[Towards Distributed Semi-speculative Adaptive Anisotropic Parallel Mesh Generation](https://arxiv.org/html/2312.13433v1)；Borrell 等，2019会议/2020预印本，[Parallel SFC-based mesh partitioning and load balancing](https://arxiv.org/html/2007.03518v1)。

HXT 的限制也应正面保留：小网格的边界冲突与调度开销较大；论文根据冲突比例减少线程，极端时回到单线程以保证终止。CDT3D论文报告的是适应网格的早期实现，接口移动层数和迭代数影响质量及扩展性，并非本项目CAD封闭体建网的即插即用替代。

不优先采用“换更复杂的预测器”“单换 METIS 为 SFC”或“无限制工作窃取”。前两者没有消除对单次重建耗时预测的依赖，后者仍不能拆分已经开始的建网操作，并可能增加跨节点依赖。更换线程/运行时本身也不构成算法创新。

## 推荐的新研究主线：保持分区边界，协作处理活动网格操作

这是待实现和验证的设计方向，不是已证明有效的新算法：

- 保留已验证的稀疏面依赖交换，外部几何及分区共享面作为约束。
- 每个原始局部子域只建立一份活动网格；将内部待插点、待改善单元及其空腔依赖作为工作单元。
- 优先让同节点空闲计算核协作处理合法且互不冲突的操作。跨内部工作分区的冲突操作延后或重新分组；外部共享面只能按一致性协议处理，不可各自修改。
- 调度依据当前剩余操作和实测完成速度，减少对事前“预测完整建网耗时”的依赖。局部操作成本也不相等，不能再把任务数平衡直接等同于时间平衡。
- 同节点协作仍不足时，才研究有界邻域的活动网格迁移：迁移当前状态及未完成操作，计入迁移、接口恢复与冲突重试费用，不重新从封闭面独立建网。

当前代码在 `occmesh_MPI_main.cpp` 的 `local_volume_mesh` 阶段一次调用 `Ng_GenerateVolumeMesh`；CMake链接外部 `libnglib.so`。本仓库没有提供该定制库内部的可暂停建网、空腔任务队列和活动状态迁移接口。因此下一次实现应先检查与集群二进制对应的定制 Netgen 内核源码，确认能否暴露并行局部操作；若不具备，明确选择内核改造或 HXT/CDT3D 后端适配。不能在当前封装层伪造“内部细粒度均衡已完成”。

固定总核数是比较前提。若采用节点内线程团队，应相应减少 MPI 进程或分配线程预算，不能沿用16进程/节点又给每进程16线程；线程团队也不会自动获得其他进程私有的 Netgen 网格状态。更换后端须核对表面约束、材料区域、尺寸场和质量，不能只比较建网秒数。

## 后续实验的唯一主判据

相对本次固化的 sparse 基线，在同样资源和几何/尺寸/质量要求下，完整后粗网格核心时间是否稳定下降。并列记录实际单元数与总工作量、局部建网最长完成时间和进程到达差、所有新增协作费用。先做单节点的真实内核原型，确认一个慢子域能被多个核实际协作加速且不增加独立建网次数，再进入多节点；不直接重跑完整超大规模矩阵。

如果原型只能降低等待但增加核心时间，或收益依赖增加工作量/放宽质量，就不升级为默认方案。不同后端产生单元数量可能不同，应报告相同精度/质量约束下的时间与实际规模，不能冒称完全相同网格的强扩展。

已有 HXT、SFC、半推测执行和对象迁移均是借鉴来源。可能的论文贡献只能是本流程中保持共享面依赖的协作机制、可验证的一致性与终止条件，以及包括新增成本在内的实测净收益；目前尚不能把它们列为已经成立的创新点。
